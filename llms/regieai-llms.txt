## Agent access — read this first

Regie.ai has **no public developer API**. There is no developer portal, no API reference, no
OpenAPI or AsyncAPI document, no published webhook catalog, no SDK on any package registry, and
no public Postman collection. Everything below is what actually exists.

- **MCP server (gated).** `https://mcp.regie.ai/mcp` is live and requires an `x-api-key` header
  plus workspace and user identifiers. Anonymous `tools/list` returns HTTP 401, so the tool
  surface cannot be enumerated. Regie.ai does not document this endpoint anywhere public.
- **No A2A agent card.** `/.well-known/agent-card.json` and `/.well-known/agent.json` return 404
  on www.regie.ai and 401 on the API hosts. app.regie.ai answers 200 with its React SPA shell
  for every `/.well-known/*` path — an HTML shell, not a document.
- **Application backends are private.** sales-prod-api, agents-api, dialer-api, transcript-api,
  user-management and marketing-api under regie.ai each serve a health check at `/` and return
  401 "Authorization header not provided" everywhere else. They are first-party app backends,
  not a product.
- **Documentation is customer-only.** help.regie.ai returns HTTP 403 behind a Cloudflare
  challenge and redirects to `/hc/restricted`; its Zendesk Help Center API returns 401.
